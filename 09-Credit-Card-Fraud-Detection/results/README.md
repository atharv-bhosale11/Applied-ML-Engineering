# Model Evaluation Results

## 📌 Overview

This directory contains the evaluation results, model comparison reports, prediction error analysis, and visualizations generated by the Credit Card Fraud Detection project.

These results help evaluate model performance, compare classification algorithms, analyze prediction errors, and understand the impact of class imbalance.

## 📂 Files Description

### 1. Feature_Importance.csv
Contains the feature importance scores extracted from the trained model to identify which features contribute most to its predictions.

### 2. Final_Model_Metrics.csv
Contains the final model's evaluation metrics calculated on the test dataset.

Metrics include:
- Accuracy
- Precision
- Recall
- F1-Score
- Average Precision
- ROC-AUC

### 3. Imbalance_Comparison.csv
Contains the Average Precision scores obtained when comparing different class imbalance handling techniques.

Techniques include:
- Class Weights
- SMOTE
- Random Undersampling

### 4. Model_Comparison.csv
Contains the evaluation results of the classification models used in the project.

Models include:
- Logistic Regression
- Decision Tree
- Random Forest
- Gradient Boosting
- Linear Support Vector Machine (Linear SVM)

### 5. Prediction_Errors.csv
Contains incorrectly classified transactions, including false positives and false negatives.

This file helps analyze the types of mistakes made by the trained model.

### 6. Threshold_Analysis.csv
Contains classification threshold analysis results, including Precision, Recall, and F1-Score for different thresholds.

These results help select a suitable classification threshold.

### 7. Tuned_Model_CrossValidation.csv
Contains cross-validation performance results for the tuned Logistic Regression model.

The results summarize performance across multiple stratified folds.

## 📊 Visualizations

The project also generates the following visualizations:

## 🎯 Project Objectives

The results are used to:

- Evaluate classification model performance.
- Compare different Machine Learning algorithms.
- Analyze fraudulent transaction detection.
- Examine false positive and false negative predictions.
- Select an appropriate classification threshold.
- Compare class imbalance handling techniques.
- Evaluate model performance using cross-validation.

## 📈 Evaluation Metrics

The project uses the following metrics:

| Metric | Purpose |
|---|---|
| Accuracy | Measures the proportion of correctly classified transactions. |
| Precision | Measures how many predicted fraud transactions are actually fraudulent. |
| Recall | Measures how many actual fraudulent transactions are detected. |
| F1-Score | Balances Precision and Recall. |
| Average Precision | Summarizes Precision-Recall performance across thresholds. |
| ROC-AUC | Measures the model's ability to distinguish between the two classes. |

**Note:** Because fraudulent transactions are rare, Accuracy should not be used as the only measure of model performance.

## ⚠️ Important Information

- Results depend on the dataset, model configuration, and classification threshold.
- CSV files contain numerical evaluation results and analysis outputs.
- PNG files provide visual representations of the analysis.
- The original dataset is available from Kaggle and is not included in this directory.
